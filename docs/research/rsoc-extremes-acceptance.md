# Separate RSOC Extreme Replay

`scripts/accept_rsoc_extremes.py` audits the separate 76 CUDA projection nodes.
It does not expand the fixed thirteen-case producer or an existing acceptance
allowlist. It never imports Torch, a producer/test factory or a solver.
Decimal precision 1100 and Fraction original inequalities independently
replay the represented input, both projections, coordinate error, original
cone membership and scaled Moreau reconstruction/orthogonality.

The exact 38 vectors and primal/dual identity domain are versioned independently.
Binary64 remote heads are `2**600`; binary32 counterparts are explicitly
`2**100`. Interior inputs retain their bits and a representable small head
cannot be hidden by a tolerance scaled to the largest coordinate.

The caller supplies independently retained SHA256 pins for the immutable
worker result, run, JUnit and collected Job/Pod status. Every node must bind a
unique hashed external sidecar with the complete versioned schema. Snapshot,
Python source membership, current numerical source, loaded-source declarations,
worker and actual Pod command/environment/resources, controller UID, completion,
zero restarts, runtime and nonempty GPU/cgroup observations must match.
Cached bytecode is not Python implementation source; unknown `.py` files and
source differences still fail. No original evidence is overwritten.

The verdict `RSOC_EXTREMES_REPLAY_PASS` is a bounded retrospective archived
numerical check. Collected Kubernetes records and tensor traces are not
cryptographic runtime attestation. The audit excludes commercial performance,
certification, all-model robustness, general conic/MIP scope and multi-GPU
scaling. It does not supply benchmark or data redistribution rights.
Synthetic unit archives are explicitly non-executed fixtures; they cannot
establish real CUDA execution, even when the same acceptance function passes.

The CLI requires `--result`, `--run`, `--junit`, `--status`, corresponding
`--*-sha256` arguments, `--current-root`, and a new external `--artifact-dir`.
It writes `acceptance.json`, `execution.log`, and a first-cause `failure.log`
when rejected. The caller pins are trust anchors, not an authorization record.
Tests are self-contained and need no historical campaign directory.

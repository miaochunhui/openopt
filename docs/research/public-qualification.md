# CPU Public Model Qualification

## Contract

`scripts/qualify_public_qp.py` consumes an **externally pinned** frozen corpus
from the read-only `public_qp_corpus.py` importer. It performs exactly one fresh
CPU float64 solve per case with openopt, OSQP and Clarabel. Openopt explicitly
enables `dual_gap_termination`, `direction_termination` and `adaptive_rho`.
It never acquires files, installs dependencies, creates planted witnesses,
automatically retries, silently changes backend, or schedules GPU work.
Any non-`cpu` device is rejected, including explicit CUDA requests. Future GPU
coordinator extensions need their own placement and end-to-end acceptance.

Every case/backend stays in the denominator, including unknown, inaccurate,
unsupported, failed and not-attempted outcomes. Exceptions retain traceback,
chained first cause, case/backend and exit code. Unrelated backends may complete
their single attempt after a backend error; this is not a retry. A missing
opt-in source API yields `UNSUPPORTED`, never residual-only fallback.

This runner makes no license/redistribution, industrial coverage, commercial
parity, speedup, representative-corpus or exact-certificate claim. No real
public model was acquired by this seat. Synthetic MPS fixtures validate only
format and functionality and can never produce public qualification PASS.

## Input And Source Review

The importer verifies original raw bytes, frozen arrays, schema, provenance
membership and matrix/bound/offset/sense semantics. This runner borrows that
verification and does not replace it with a second parser or a generated QP.
An empty corpus, wrong manifest pin or changed input fails before solving.

`origin=public` is a **declaration**, not public authenticity. Without separate
caller-pinned public source acceptance, a numerically successful run remains
`UNQUALIFIED`. Reserved/test source hosts and synthetic/fixture/planted markers
are rejected from public coverage even if labelled public. Industrial count is
always zero. Public source acceptance is an explicit external trust boundary:
hashes cannot prove an independently dishonest review true. It is not a license
claim and must not be self-generated by the runner or substituted for acquisition
evidence.

The optional source-review JSON has exactly these fields. Its ordered cases
must match all publicly declared frozen cases, and its corpus pin must be the
same externally supplied `corpus.json` hash:

```json
{
  "schema_version": 1,
  "verdict": "PUBLIC_SOURCE_ACCEPTED",
  "corpus_sha256": "EXTERNALLY_PINNED_CORPUS_SHA256",
  "cases": [{
    "case_id": "FROZEN_CASE_ID",
    "source_url": "EXACT_FROZEN_SOURCE_URL",
    "input_sha256": "EXACT_FROZEN_INPUT_SHA256",
    "model_sha256": "EXACT_FROZEN_MODEL_SHA256",
    "source_review": "Independent acquisition/source review, not a license verdict",
    "evidence_sha256": "EXTERNALLY_REVIEWED_ACQUISITION_EVIDENCE_SHA256"
  }]
}
```

Real acquisition belongs exclusively to the acquisition seat. The main
coordinator supplies frozen inputs and, if independently accepted, this pinned
review. This runner has no download or network path.

## Numerical Acceptance

Original `P,q,A,l,u,variable_lower,variable_upper,offset` and coordinate names
are preserved byte-for-byte. The view appends identity rows for original
variable bounds and changes objective sign only for maximization; there is
no variable shift, presolve, projection, clipping or regularization by the
checker. All backends solve that identical view from fresh workspaces.

Every returned finite x/y is checked by `check_qp_candidate` on original
coordinates, including feasibility, stationarity, strict infinite-bound signs,
complementarity, numerical dual availability and **signed dual gap**. Solver
residuals are not accepted as an oracle. Strict solved status, all candidate
checks and agreement of reported/core objective are required for optimality.
Inaccurate/unknown/max-iteration status remains unqualified even if its saved
candidate happens to pass.

Original objective is always `0.5*x.T@P@x + q.T@x + offset` with original sense.
The normalized dual is mapped back with the same offset and sense, becoming a
numerical upper objective for maximization. Offset is not allowed to widen the
independent gap or reference agreement threshold. Both centered and original
objective values, plus original signed gap, are retained.

Infeasibility and unboundedness require strict status and independent generated
direction evidence. Primal unboundedness also needs an independently feasible
base from **that same solve's host output**. A reference certificate without a
feasible base is not promoted to unboundedness. No planted oracle point,
another backend's solution, auxiliary feasibility solve or retry is used.

Matched eps/iteration limits and effective settings are recorded: OSQP also
records certificate eps, check interval, adaptive/scaling/rho/sigma/alpha
controls, with warm starting and polishing disabled. Clarabel records gap,
feasibility and infeasibility eps, maximum threads/iterations, with presolve
and equilibration disabled. Algorithms have different stopping rules; this is
not a claim of identical internal work. Every backend uses the same independent
acceptance eps and checker. All openopt/reference pairs are retained, not only
jointly solved pairs, and both references must independently qualify and agree.

## Run And Input Replay

Use the existing CPU environment. `--source-root` defaults to this runner's
repository and may explicitly point to the current main repository. The chosen
QP/checker source is copied and loaded in a private namespace, preventing an
installed older package from silently replacing it. Source code is read-only;
the selected required opt-in API must actually exist. The parser is also read
from `--source-root/scripts/public_qp_corpus.py` and must match the frozen
importer SHA256. This permits the main repository's NAME/SIZE-compatible
parser without editing the seat's read-only baseline parser.

CLI shape (pins and acquisition paths must come from the main coordinator):

```text
qualify_public_qp.py run --corpus FROZEN_DIRECTORY --manifest-sha256 EXTERNAL_CORPUS_PIN --artifact-dir NEW_EXTERNAL_DIRECTORY [--source-root /data/dev/openopt] [--public-acceptance REVIEW_JSON --public-acceptance-sha256 EXTERNAL_REVIEW_PIN]
qualify_public_qp.py replay --result RESULT_JSON --result-sha256 EXTERNAL_RESULT_PIN
```

Artifacts must be new exclusive directories under
`/hf3fs-jd/data/tmp/openopt-release-20261010/public-qualification/` for this seat.
Existing failed or successful evidence is never overwritten.

`result.json` pins every sidecar by SHA256 and byte size: frozen original input
manifest/corpus/raw/NPZ/metadata/reader logs, every attempt's JSON and CPU
float64 host-vector NPZ, exception logs, source review and the exact runner,
importer, QP and independent checker source snapshots. NPZ contains numerical
arrays, never object arrays or pickle; nonfinite backend-reported scalars stay
in the numerical sidecar and are not converted into JSON false success.

Replay needs only the result directory and its **externally pinned result
hash**, not the original corpus directory, current solver source or another
solve. It validates all sidecar pins, re-verifies frozen raw semantics, reruns
the saved-source independent checker on host vectors, checks source eligibility,
strict statuses, original objectives, all rows, pairs and aggregate denominators.
It neither repairs failed evidence nor reacquires or re-solves anything.

Exit codes apply to both run and replay: `0=PASS`, `1=UNQUALIFIED`, `2=FAIL`.
`REPLAYED` means integrity/numerical reproduction, not public PASS; replay
preserves the original qualification exit code. Source/infrastructure/input
execution failures remain FAIL with their first-cause evidence. A global
preflight FAIL replay verifies pinned artifacts/logs but explicitly reports
zero numerically replayed attempts.

The explicit three-file seat assignment excludes `docs/qp-design.md` and
generated reports; methodology integration there is owned by the main
coordinator. Infra's edit router rejects this worktree as outside infra;
no infra rule changes or identity/path bypass was made.

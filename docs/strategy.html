Product decision / 2026-10-10

Commercial Ambition. Open Implementation. GPU Acceleration.

openopt aims to match leading closed-source optimizers on supported problem classes, then demonstrate GPU advantages where the workloads justify them. There is no universally best solver declared here. Current code is the OpenPO portfolio foundation, not yet a general LP/QP, conic or mixed-integer release.

Each stage needs a domain-neutral model and result contract, not renamed portfolio classes. Nonconvex/global optimization, nonlinear programming, constraint programming and SDP are not implied by the general-purpose ambition. They require separate scope, implementation and evidence.

GPU Execution

Design GPU-resident dense, sparse and matrix-free operators; batched solves; reusable prepared workspaces; and measured presolve/scaling and transfer costs. Triton and PyTorch CUDA are existing foundations, not automatic performance wins. Verify returned tensor placement on the requested device. Reject missing or incompatible explicitly requested GPUs rather than falling back silently.

CPU references and measured automatic routing remain useful for small, sparse or accuracy-sensitive cases. Single-GPU compatibility does not qualify multi-GPU scaling. Keep dense, sparse, batched, cold-start and warm-start performance claims separate.

Commercial Qualification

Before a run, freeze problem sets and hashes, canonical objective/constraint formulations, dtype, accuracy thresholds, limits, seeds, hardware allocation, solver versions/settings and licensed execution permissions. Use held-out cases and publish per-instance results, including failures and censored time limits. Do not cherry-pick only converged instances or convenient problem families.

Correctness gates cover feasible, infeasible, unbounded, degenerate, ill-conditioned and invalid inputs; primal/dual residuals, objective gaps and termination status. MIP additionally needs integrality, best bound, optimality gap and certificates; heuristic quality is not proof of optimality.

Performance gates include end-to-end transfer-inclusive cold/hot latency, p50/p95, solved count, success rate, throughput, peak host/GPU memory and paired speedup distributions. Record warm-up and compilation separately. Compare commercial defaults and documented tuning without suppressing either arm. Accuracy and reliability must pass before a speedup is accepted.

Gate states: PASS only for measured, supported scope; FAIL for a violated frozen criterion; UNVERIFIED for missing licenses, hardware or evidence. Open-reference tests cannot substitute for an unrun commercial comparison. Do not install commercial SDKs, change license servers or disclose credentials as a side effect of this product decision.
